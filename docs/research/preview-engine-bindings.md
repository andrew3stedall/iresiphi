## Recommended pinned baseline

Choose DataFusion **55.2.0**, PyO3 **0.30.1**, maturin **1.16.0**, calamine **0.38.0**, serde_json **1.0.154** with `raw_value`, and csv **1.4.0**. Evaluate Polars at Rust crate **0.55.2**, not at the independently numbered Python release. Pin direct versions exactly and commit Cargo.lock during implementation; use DataFusion's Arrow re-export to avoid independently selecting an incompatible Arrow family. Rust **1.94.0** is the proposed toolchain baseline: the crates.io version metadata reports this as DataFusion's minimum, versus PyO3 1.85, calamine 1.88 and maturin 1.89. These are metadata observations, not a successful combined build. ## Engine suitability

Documented at DataFusion 55.2.0: an embeddable Rust engine, Arrow batches, logical/physical plans, DataFrame expressions, extensibility and built-in file readers. This is enough machinery for typed relational lowering without exposing SQL to callers. Build an Iresiphi semantic plan first, then lower validated operations into DataFusion expressions. Explain must retain the semantic plan and source references, rather than treating optimizer output as the public contract. [DataFusion API](https://docs.rs/datafusion/latest/datafusion/).

Documented at Polars 0.55.2: lazy expressions, joins, grouping and projections; Rust Decimal and Date types exist. The Rust API is synchronous and recommends `spawn_blocking` in async applications. It is a credible alternative for this bounded workload. The sources do not establish an equivalent per-query memory-reservation contract or bounded cancellation latency. Absence of evidence here is not a claim that Polars cannot cancel or stream. Nor should old claims that its decimal type is unstable be repeated: the current Python decimal page inspected did not carry that warning. Prefer DataFusion for the explicit execution-resource integration surface, not an unmeasured speed advantage. [Polars Rust API](https://docs.rs/polars/0.55.2/polars/), [Rust datatypes](https://docs.rs/polars/latest/polars/datatypes/enum.DataType.html), [current decimal documentation](https://docs.pola.rs/api/python/stable/reference/api/polars.datatypes.Decimal.html).

## Exact arithmetic and wrapper semantics

Arrow documents Decimal128 precision/scale and Date32 representations. Representation alone does not prove multiplication, rescaling, overflow, or aggregate behavior in a particular engine. DataFusion has binary type-coercion machinery; the inspected coercion page was 54.0.0, so it is not evidence for exact 55.2.0 coercion rules. [Arrow types](https://docs.rs/arrow-schema/latest/arrow_schema/enum.DataType.html), [coercion page](https://docs.rs/datafusion-expr/latest/datafusion_expr/type_coercion/binary/index.html).

Recommended preview subset: signed decimal coefficients with declared precision at most 38 and scale 0–18; require product precision/scale to fit that subset before execution, otherwise reject. All parse, multiply, subtract, sum and rescale operations must be checked. Reject excess fractional digits unless an explicit rounding operation is declared; do not silently truncate, wrap, saturate, convert to float or turn arithmetic failure into null. For this preview, reject recipes needing rounding instead of inventing a currency rule. Require exact representability at the declared output scale. Checked wrapper kernels may be needed if native kernels cannot satisfy this contract. This is necessary wrapper behavior, not a claim already verified for DataFusion.

Preserve original numeric tokens; accept decimal strings or exact numeric lexemes, never route money through f64. Currency is a declared field/constraint, not encoded by Decimal128. Restrict the acceptance fixture to one currency. Keep unresolved expected charge/variance null with an explicit reason, distinct from zero and distinct from an execution error. Sum comparable billed/expected/variance separately from full billed population and unresolved billed amount.

Own join meaning in Iresiphi. Give every invoice line stable identity scoped to source/invoice; join supplier plus translated item and declared context, never item alone. Count valid candidates per line before selection: zero is unresolved, one resolved, more than one ambiguous. Never pick first/last or deduplicate an ambiguity silently. Preserve all requested lines using left-preserving assembly. Linked components stay in a separate detail relation; aggregate at declared grain before safe broadcast. Verify uniqueness at every many-to-one boundary and enforce output row/population invariants after optimized execution. Engine cardinality estimates are not validation.

Recommended validity rule: date-only ISO Gregorian invoice dates, start-inclusive/end-exclusive intervals, with null end explicitly meaning unbounded. Reject missing required dates, invalid dates, start >= end and ambiguous overlaps. Apply supplier/item equality and date eligibility before counting candidates; a post-left-join WHERE must not discard unmatched lines. A general temporal/as-of join is unnecessary. Preserve candidate IDs and rejection reasons for inspection. These interval policies are recommendations for downstream decisions, not resolutions already agreed in the workflow.

## Resource limits and cancellation

Documented at DataFusion 55.2.0: MemoryPool accounts for participating large operators, not all allocations, source buffers or batches. Failure to reserve can spill or error depending on operator. It is not a whole-process RSS ceiling. [MemoryPool](https://docs.rs/datafusion/latest/datafusion/execution/memory_pool/trait.MemoryPool.html).

Recommended initial profile, subject to measurement: one concurrent run, two execution partitions, 8,192-row batches, 256 MiB engine reservation budget, no spill, 64 MiB per input file, 256 MiB total input bytes, 256 MiB decoded XLSX bytes, one million decoded cells per worksheet, 1 MiB maximum field/token, nesting depth 64, 100,000 invoice lines, one million components, 100,000 rows per lookup and 256 MiB serialized result budget. Abort before publishing a result when any configured limit is exceeded. These are proposed admission limits, not measured capacity promises; the generated workload must fit them or the profile must be revised with evidence. Cap candidate expansion before materializing large joins. Parser, retained provenance and Python result memory require separate accounting. An in-process library cannot promise a hard RSS or kill deadline; users needing that must use an isolated process/container with OS enforcement.

Documented execution contract: dropping DataFusion result streams must free resources and abort spawned work; operators must yield for timely cancellation. This does not prove a universal latency bound. Own a cancellation token, check it in parsing and output loops, and drop all result streams on cancellation/error. Do not assume dropping an async handle interrupts a blocking XLSX parse. No partial result is successful; staging cleanup and final bundle publication must be failure-safe. [ExecutionPlan cancellation](https://docs.rs/datafusion/latest/datafusion/physical_plan/trait.ExecutionPlan.html).

## Input adapters

JSON: use serde_json raw values to preserve original numeric lexemes and raw document bytes plus JSON paths. Explicit header/line-array projection produces typed batches; reject duplicate keys, unexpected types and missing required fields rather than inferring business schema. RawValue preserves source formatting but does not itself implement all these checks. [RawValue, displayed 1.0.154](https://docs.rs/serde_json/latest/serde_json/value/struct.RawValue.html).

CSV: csv 1.4.0 provides configurable reader/writer builders, UTF-8 StringRecord and source-position support. Declare delimiter, quoting, headers, null tokens and typed columns. Preserve record identity and original field text; reject invalid UTF-8, ragged rows and malformed decimals. Escape CSV output correctly and serialize money as decimal text. [csv API](https://docs.rs/csv/latest/csv/).

XLSX: calamine 0.38.0 reads cell values and formula metadata; Data includes Float(f64), Int, String, DateTime, Error and Empty. This is not an exact-decimal source representation. Require money/rate/quantity columns used in exact arithmetic to be text decimals (or validated integer cells); reject floating numeric cells in those columns. This restriction still permits XLSX enrichment and prevents fabricating decimal fidelity from a float. Numeric Excel dates need explicit epoch handling and tests for 1900/1904 workbooks; reject the fictitious 1900 leap-day and fractional date-only values. Prefer declared ISO date text for the initial fixture. [calamine API](https://docs.rs/calamine/latest/calamine/), [Data variants](https://docs.rs/calamine/latest/calamine/enum.Data.html).

Declare sheet/header/columns. For formula cells require a usable stored cached value; never evaluate formulas, refresh links or execute macros. Compare formula metadata with cached value presence; missing cache and cell errors fail. Distinguishing empty cached strings from absent caches is an integration gate. Cache freshness cannot be certified by this reader. Retain source workbook bytes, sheet and cell coordinates for reconciliation; typed cells alone do not preserve raw XML or display formatting. Preflight archive entry sizes and enforce actual decompression/cell limits; range allocation must not bypass admission checks. Resolve local roots safely and reject remote URLs and path escapes in every adapter.

## Python boundary and packaging

PyO3 0.30.1 documents CPython 3.9+ support, Python-owned object lifetimes, PyErr exceptions, and `Python::detach`/`check_signals`. Thus ordinary GIL-enabled CPython 3.12 and 3.13 are reasonable targets, but support is not proof that this complete engine wheel builds. Build separate cp312/cp313 Linux x86_64 wheels initially; defer abi3, free-threaded 3.13, PyPy and other platforms. Use maturin 1.16.0 and a pinned manylinux_2_28 x86_64 build image, declaring glibc >=2.28; run the wheel audit and test in clean minimum-glibc containers. Do not use `target-cpu=native`. [PyO3](https://docs.rs/pyo3/0.30.1/pyo3/), [Python token methods](https://docs.rs/pyo3/0.30.1/pyo3/marker/struct.Python.html), [maturin distribution](https://www.maturin.rs/distribution.html).

Keep one Rust semantic implementation. Python owns opaque recipe/result handles backed by owned Rust state, not borrowed Python buffers. Detach during execution; no Python callbacks in workers. Reattach on the Python calling thread to check signals and translate interruption into the shared cancellation path. Use stable error codes with stage/source/row context, mapped to Python exceptions; do not expose engine errors as the stable API.

Internal interchange: typed Arrow RecordBatch with explicit schema, decimal precision/scale, Date32 and validity bits, owned through Rust reference counting. Python materialization copies into Python int, Decimal constructed from exact text, date, None and strings; never Python float for exact values. Make close/drop release handles predictably and reject access after close. No PyArrow dependency, dataframe input, Arrow C-data export or zero-copy Python guarantee is needed for the scoped preview. Recipe reopening uses versioned logical declarations and rebinding, not serialized engine pointers or physical plans.

## Implementation acceptance gates

1. Locked Rust build and audited cp312/cp313 wheels install/import and execute the same public validate/explain/run fixture on clean Linux x86_64. Record exact compiler, lockfile, image digest and wheel tags.
2. Exact decimal cases include 0.1 × 0.2, mixed scales, large integers beyond 2^53, maximum precision, negative variance, overflow in multiply/subtract/sum, excess scale and nulls. Compare to an independent integer-coefficient oracle; assert result schema as well as values. Any implicit float or unchecked arithmetic blocks release.
3. Two-supplier fixture returns comparable 160/145/15, full billed 180 and unresolved 20. Duplicates, overlapping dates, null keys, boundary dates and component fanout preserve the line population and produce the required diagnostics.
4. Real JSON/CSV/XLSX files exercise exact lexemes, duplicate JSON keys, quoted CSV/newlines, cached/missing-cache formulas, numeric-versus-text money, empty cells, error cells, both Excel epochs and oversized ZIP/range rejection. Verify source paths/cell references survive.
5. Run 100,000 generated lines with variable components under the declared profile; measure peak RSS, tracked reservations, elapsed time and output size. Force low budgets, cancellation during parsing/join/output, Ctrl-C, repeated runs and dropped Python handles; verify cleanup and no successful partial publication. Report cancellation latency without claiming a hard bound.

These gates belong to implementation acceptance. The documented mechanisms and explicit restrictions are sufficient to choose the stack now; no performance ranking or successful integration has been asserted.
